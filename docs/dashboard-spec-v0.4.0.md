# 京小电获客工作台｜深色专业玻璃态看板 v0.4.0

结论：v0.4.0 把 v0.3.1 的三页原型补成一套完整的获客工作台设计基线，包含 10 个视图、全局覆盖层、组件状态库、响应式规则和数据视图模型契约。设计仍以方案一原色板与深色玻璃态为准；当前 JXD-LEADS-001 的前端与数据接口被视为“待升级的接入环境”，不反过来约束设计稿。

## 0. 版本关系

- v0.4.0 是当前设计基线，源文件为 design/index.html、design/styles.css、design/app.js。
- v0.3.1 完整归档在 archives/2026-11-16-v0.3.1-complete/，保留 44px 标题通栏、三页结构与全部旧样式，可回退比较。
- v0.3 的 87px 标题通栏、v0.2 照片 Hero、v0.1 指挥面板分别在 archives/2026-11-16-v0.3-header87/、archives/2026-11-16-v0.2-photo-hero/、archives/2026-11-16-v0.1-command-center/。
- 本版不覆盖旧版本；新增页面与覆盖层只追加在 v0.4.0 源文件中。

## 1. 设计定位与边界

| 项目 | 决定 |
|---|---|
| 视觉方向 | 深色专业玻璃态 SaaS 工作空间，保留方案一原色板与暖橙主强调 |
| 业务角色 | 京小电获客工作台：线索、客户项目、采购机会、跟进日程、渠道与转化复盘 |
| 当前工作台 | 只作为未来接入端；前端结构、接口和空态仍会升级，本设计不绑定其现有模板 |
| 页面规模 | 9 个业务视图 + 1 个设计基线视图；桌面优先，移动端保留轻查看 |
| 数据边界 | 原型全部为示例数据；真实联系人、预算、采购阶段仍需人工确认 |
| 设计交付 | 可交互单文件预览、设计规范、令牌、可复用 skill 与视图模型契约 |

设计原则：

1. **先判断，再行动**：每页首屏回答“现在最该处理什么”，而不是堆满指标。
2. **玻璃只做分组**：6–10% 白色叠层、22px blur、10% 白边、顶部内高光；不用实心灰模拟玻璃。
3. **未知保持可见**：预算、数量、采购角色未知时显示“未知/待核实”，不用行业均值补齐。
4. **人工确认优先**：AI 只进入待审，采购/复购、报价、停联与客户消息不自动执行。
5. **覆盖层有层级**：全页做复杂任务，抽屉保留上下文，弹窗只做短确认，命令面板负责跳转。

## 3. 页面结构

### 3.1 统一骨架

- 顶栏 80px：菜单/面包屑、搜索（⌘K）、统计周期、通知、设置、当前用户。
- 侧栏 256px，可折叠到 84px；≤1024px 改为抽屉。
- 内容最大宽度 1480px，左右 22–24px；≤640px 收缩到 11–16px。
- 页面标题通栏 44px：24px 标题 + 10.5px 副标题 + 右侧摘要 + 页面动作；≤1100px 隐藏摘要，≤820px 纵向。
- 页脚：版本与“示例数据”声明，≤640px 纵向。

### 3.2 获客总览

保留 v0.3.1 的 Hero、KPI、漏斗、渠道环图、金色趋势和机会卡。新增：

- 标题区右侧摘要与迷你趋势。
- Hero「查看今日队列」跳到跟进日程；「新建线索」打开新建抽屉。
- 线索列表「查看全部线索」进入线索池；筛选按钮打开筛选抽屉。

### 3.3 线索池

- 工具栏：搜索、筛选、阶段下拉、排序、状态预览（正常/加载/空态/错误）。
- 表格列：选择、线索、来源、阶段、优先级、下一步、负责人、更新、更多。
- 批量条：已选数量、分配、标记已联系、归档、取消选择。
- 底部：显示范围/总数、分页。
- ≤820px 表格改为卡片行：名称、来源、阶段/优先级、下一步、负责人；不横向溢出。
- 状态预览只用于设计评审，正式接入时移除；真实空态由数据决定。

### 3.4 客户项目

- 4 个摘要块：需求确认、报价/试样、采购/复购、阶段停留超 14 天。
- 项目卡：名称、客户/场景、阶段进度 1/4–4/4、负责人、关联线索、下一步、风险、阶段标签。
- 点击卡片打开项目抽屉；抽屉展示关联线索与下一步；新建项目走新建抽屉。
- 阶段推进必须人工确认，不做拖拽自动推进。

### 3.5 采购机会

- 四列看板：待核实、需求确认、报价/试样、采购/复购。
- 卡片：名称、地点、数量/未知、数量说明、采购角色、负责人、下一步、风险。
- ≤1024px 看板横向滚动，列宽 250px；页面本身不横向溢出。
- 每列底部“新建机会”进入新建抽屉；卡片点击打开机会抽屉。
- 采购/复购阶段由人工确认；AI 只给建议。

### 3.6 跟进日程

- 周视图：7 个日期，显示任务点与数量；逾期用红色点。
- 当天议程：时间、类型图标、标题、备注、负责人、逾期标签。
- 今日重点：逾期与今日事项；点击打开任务抽屉。
- 跟进规则：每次沟通留结果与下一步；逾期优先；AI 草稿不自动发送。
- 支持上一周/本周/下一周；空日显示空态并可新建跟进。

### 3.7 转化报告

- 摘要块：周报数量、月报数量、渠道复盘数量、待补口径数量。
- 报告卡：标题、周期、状态、更新时间、三项指标、迷你柱状图、摘要。
- 点击打开报告抽屉；导出走导出弹窗；报告口径单独成卡。
- 待生成报告显示“待生成”，不伪造结果。

### 3.8 团队与设置

- 个人与工作空间：显示名称、角色、工作空间、时区。
- AI 与审核规则：三条锁定开关（待审、保留来源、未知留空）。
- 通知：逾期、待核实、AI 待审、每周摘要。
- 数据与备份：立即备份、导出、恢复。
- 外观：信息密度、减少动效。
- 危险区：归档工作空间，必须输入“归档”才能确认。
- 侧栏：当前环境、最近操作、设计说明。

### 3.9 设计基线

用于后续看板复用的组件画廊：

- 8 个颜色令牌与 3 种玻璃材质。
- 5 级排版。
- 按钮 8 态（Default/Hover/Focus/Active/Loading/Disabled/Glass/Danger）。
- 表单 6 态（Default/Focus/Error/Disabled/Select/Textarea）+ 复选/单选。
- 标签：状态、优先级、字段状态、示例。
- 数据状态：空、加载、错误、无结果。
- 覆盖层 6 级：Page / Drawer / Nested drawer / Modal / Command / Toast。
- 可访问性 5 条基线。

## 4. 视觉系统

### 4.1 色彩

| 令牌 | 值 | 用途 |
|---|---|---|
| 背景 | #1A1A1A | 页面底 |
| 主体层 | #2D2D2D | 工作区容器 |
| 导航玻璃 | rgba(45,45,45,0.8) | 顶栏 |
| 侧栏玻璃 | rgba(45,45,45,0.6) | 侧栏 |
| 卡片玻璃 | 6–10% 白叠层 | 卡片/KPI/图表 |
| 行玻璃 | rgba(70,70,70,0.3) | 列表行 |
| 边框 | rgba(255,255,255,0.10) | 卡片 1px |
| 橙红 | #FF6B35 | 主操作、漏斗、待推进、逾期 |
| 暖橙 | #FFB347 | 中间强调、渐变 |
| 金色 | #FFD700 | 趋势线、选中态、关键数值、阶段进度 |
| 成功 | #4CAF50 | 已核实、完成 |
| 警告 | #FFC107 | 待处理、阶段停留 |
| 危险 | #F44336 | 逾期、风险、危险区 |
| 信息 | #2196F3 | 中性数据 |

规则：橙色代表“要行动”，金色代表“高价值/高意向”，绿色代表“已发生的好信号”。颜色不能作为唯一信息，状态标签必须带文字。

### 4.2 玻璃

| 层 | 参数 |
|---|---|
| 卡片 | 6–10% 白、22px blur、10% 白边、顶部 11% 内高光、0 24px 60px rgba(0,0,0,0.33) |
| KPI | 20px blur；hover 提亮边框，不上浮 |
| 抽屉/弹窗 | 26px blur、saturate 120%、10–12% 白边、内高光 |
| 行 | 10px blur、3–4% 白；选中时橙色 7% |
| 导航 | 24px blur、0.8/0.6 不透明度 |

不要用纯色 #2D2D2D 填充替代玻璃；背景必须有可被模糊的橙/金环境光、网格或噪点。

### 4.3 字体与数值

- 标题：Poppins 600；正文：Poppins 400；中文回退 PingFang SC。
- 页面标题 24px/600；区块标题 19px/600；指标 30px/600；正文 13px/400；标签 9px/500；微标签 8px/500。
- 关键数字使用 tabular figures；趋势/阶段进度用金色。
- 英文标签大写，字距 0.08–0.16em；中文正常字距。

### 4.4 间距、圆角与动效

- 间距：8 / 12 / 16 / 20 / 24 / 32 / 40。
- 圆角：8（按钮/输入）、12（行/摘要）、16（卡片）、20（Hero）、24（外壳）、999（pill）。
- 动效：hover 200ms、卡片 300ms、抽屉 280ms、图表 700ms；统一 cubic-bezier(0.25,0.46,0.45,0.94)。
- prefers-reduced-motion 下关闭位移与骨架动画。

## 5. 组件与状态

### 5.1 按钮

| 类型 | 用途 | 状态 |
|---|---|---|
| 白色主按钮 | 每页唯一主行动 | default / hover / focus / active / loading / disabled |
| 玻璃次按钮 | 导出、筛选、取消 | default / hover / focus |
| 安静按钮 | 忽略、清除 | default / hover |
| 危险按钮 | 归档、破坏性确认 | default / hover / disabled |
| 小按钮 | 抽屉与卡片内操作 | 32px 高 |

加载态使用 12px 旋转指示，不改变按钮宽度；禁用态保留文字可读性。

### 5.2 表单

- 标签在字段上方；必填明确标“必填”；错误信息紧贴字段。
- 默认 36px 高；focus 橙色边框 + 3px 外发光；错误 60% 红边。
- 未知可留空，不用占位符伪装成已填写。
- 开关：34×20，选中橙色；锁定开关降低透明度并禁用。
- 选择框支持键盘；错误只提示，不自动修正业务事实。

### 5.3 标签与状态

- 状态：已核实/需求确认/待补充/已逾期。
- 优先级：Critical / High / Medium / Low。
- 字段：已确认 / 待核实 / 示例值 / 未知。
- 示例数据统一“示例数据”小标签；不与真实状态混用。

### 5.4 数据状态

| 状态 | 规则 |
|---|---|
| 空态 | 说明为什么为空 + 一个下一步（新建/导入） |
| 加载 | 保留结构骨架，避免页面跳动；骨架动画尊重 reduced motion |
| 错误 | 说明可能原因（本机服务/文件占用），提供重试；不假装成功 |
| 无结果 | 由筛选/搜索导致，提供清除筛选 |
| 禁用 | 说明由系统保留或权限限制，不隐藏 |
| 无权限 | 正式接入时补；当前设计以禁用/只读替代 |

### 5.5 表格、卡片与图表

- 表格：行 hover、选中橙色 7%、逾期下一步红字、优先级标签、更多按钮。
- 项目卡：左侧 2px 状态线；hover 上浮 2px；阶段进度 4 段。
- 机会卡：数量金色、未知金色、角色/负责人小标签。
- 图表：金色趋势线 + 目标虚线；三条渠道线使用橙/绿/金；必须有隐藏数据表与方向键读取。
- 报告卡：迷你柱状图只做趋势提示，不替代完整图表。

## 6. 覆盖层与关联

### 6.1 层级

| 层 | z-index | 用途 | 尺寸 |
|---|---|---|---|
| Page | 0 | 完整页面、复杂编辑 | 全宽 |
| Drawer | 100+ | 线索/项目/机会/任务/报告上下文 | 560 / 470 / 390px |
| Nested drawer | 120+ | 记录跟进、改期 | 470px |
| Modal | 140+ | 导出、确认、破坏性操作 | 520 / 420px |
| Command | 160+ | ⌘K 搜索与跳转 | 620px |
| Toast | 2000 | 结果反馈 | 自适应 |

实现上按打开顺序递增覆盖层 z-index（每层 +20），保证键盘与视觉层级一致。

### 6.2 关联流程

1. **通知 → 记录**：通知抽屉点条目 → 关闭抽屉 → 打开记录抽屉；不叠加两层通知。
2. **列表 → 记录 → 跟进**：线索行打开记录抽屉；“记录跟进”叠加跟进抽屉；Esc 只关跟进，记录仍在。
3. **记录 → 导出**：导出弹窗叠在记录抽屉上；确认后显示成功态，可下载示例。
4. **设置 → 确认**：归档工作空间打开确认弹窗；必须输入“归档”才启用确认按钮。
5. **⌘K → 页面/记录/操作**：命令面板先关闭，再执行跳转或打开记录，避免焦点错位。
6. **切换主视图**：关闭全部覆盖层，防止上下文错位。

### 6.3 行为规则

- Esc 只关闭最上层；遮罩点击等同 Esc。
- 打开时锁定 body 滚动，背景 inert；关闭后恢复。
- 焦点陷阱限制在最上层面板；关闭后焦点归还触发元素。
- 抽屉最多两层；第三层改用弹窗或全页。
- 弹窗不超过 6 个字段；长表单用抽屉。
- 破坏性操作必须二次确认；确认文案说明影响与可恢复性。
- 抽屉不替代完整详情页，只保留上下文。

## 7. 交互规则

- AI 建议只进入待审；可以采用、忽略或复核，不自动写入阶段/报价/客户消息。
- 采购/复购阶段只能人工确认；阶段推进弹窗必须填写确认依据。
- 导出默认脱敏联系人；联系人明文需单独确认；示例导出可直接下载 CSV/Markdown。
- 筛选条件可叠加；清除筛选恢复全部；筛选不改变原始数据。
- 批量“标记已联系”只改阶段并保留记录；归档需要二次确认。
- 新建线索/项目/机会/任务先记录已知信息，未知留空；创建后进入对应页面。
- 跟进记录必须留下结果与下一步；提醒不自动联系客户。
- 逾期优先于新增事项；今日重点固定显示逾期/今日。

## 8. 数据视图模型契约

设计稿只消费视图模型，不直接读 SQLite、FastAPI 或当前模板。未来工作台升级后，在页面加载前注入 window.JXD_DASHBOARD_DATA 即可复用界面。

| 实体 | 必填字段 |
|---|---|
| lead | id, name, org, source, stage, priority, next, nextMeta, nextDate, owner, updated, tone, contact, contactMasked, qty, projectId, evidence, note |
| project | id, name, client, scene, stage, stageIndex, owner, leads, next, nextDate, risk, tone, note |
| opportunity | id, projectId, name, place, stage, qty, qtyNote, role, owner, next, nextMeta, risk, ai |
| task | id, title, leadId, projectId, date, time, owner, priority, overdue, note, icon, tone |
| report | id, title, sub, status, statusClass, updated, metrics, bars, summary, findings |
| notification | id, title, body, time, icon, tone, unread, record |

约束：

- 日期使用 ISO YYYY-MM-DD；时间使用 HH:mm。
- stage 枚举固定为待核实 / 已联系 / 需求确认 / 报价 / 试样 / 采购 / 复购。
- 未知值用 null 或“未知”，禁止用估算值补齐。
- 联系人默认只给脱敏值；明文需要单独权限。
- record 使用 lead:id / project:id / opportunity:id / task:id / report:id，供通知与命令面板跳转。
- 空数组是合法输入；所有列表与图表必须有空态。
- 图表时间序列与漏斗如未提供，显示空态，不随机补数。
- 总览 KPI、漏斗、渠道环图与趋势在 v0.4.0 仍为静态示例；正式接入前必须补 overview 聚合，或在未提供时隐藏这些模块，不能沿用示例数字。

当前 JXD-LEADS-001 的接口处于升级中；接入时只需新增一个 adapter 把已有 dashboard_snapshot() 或后续接口映射到上述结构，不要求复用当前模板的 DOM。

最小示例见 design/view-model.example.json；它只展示字段形状，不是业务数据。

## 10. 命名与维护

- 设计源唯一：design/index.html + styles.css + app.js + tokens.json；生产接入不得反向覆盖设计源。
- 版本：v0.4.0；大改版归档旧 design 目录，保留旧预览与规范。
- 命名：视图 data-view；页面模块 .xxx-card；覆盖层 data-overlay；状态 .is-*；数据钩子 data-*；不按文案写选择器。
- 新增页面清单：viewTitles → 侧栏/命令面板 → section → onView 渲染 → 响应式 → 状态（empty/loading/error）→ 文档与截图。
- 设计专用元素（状态预览、设计基线、示例标签）在正式接入时移除或隐藏；不得把演示开关带进生产。
- 令牌变更先改 tokens.json，再改 CSS 变量，最后同步规范；避免三处漂移。
- 可复用流程见管理库 skill：dashboard-design-system。

## 11. 可访问性

- 所有可点击行/卡支持 Enter / Space，有可见 focus ring。
- 图表有隐藏数据表、aria-label 与方向键读取。
- 抽屉/弹窗 role=dialog / alertdialog、aria-modal、焦点陷阱、关闭归还焦点。
- 颜色不作为唯一信息；状态带文字。
- 覆盖层打开时背景 inert；Esc 只关最上层。
- ≤640px 覆盖层全宽；无横向溢出；底部 dock 不遮挡可滚动内容。

## 13. 工作台接入建议

当前 JXD-LEADS-001 仍在升级，前端结构与接口不能作为设计约束。建议按以下顺序接入：

1. 先确定视图模型 adapter：把候选、项目、机会、跟进、通知映射到第 8 节结构；缺失字段返回 null/空数组。
2. 先接线索池/项目/日程三个读多写少页面，验证空态、权限与真实长文本。
3. 再接记录抽屉与跟进表单；所有写入保留人工确认与审计。
4. 最后接漏斗/趋势/报告；没有时间序列就显示空态。
5. 设计基线页与状态预览仅保留在内部预览，不进入正式导航。

不新建项目窗口：新看板复用 JXD-LEADS-001 的后端、数据库、备份与发布流程；设计源保留在 dashboard 项目，避免接口与部署重复。

## 15. 关键取舍

- 保留人物 Hero 与 SaaS 文案，但收敛为 96×120 负责人破框头像，避免照片抢走数据注意力。
- 联系人模块维持 42px 字母圆，不做破框；破框只用于 Hero，全页最多一处。
- 不做拖拽阶段推进：线索阶段涉及来源、审核、版本与回执，拖拽会造成“界面已完成、业务未确认”的误读。
- 不把“团队协作”做成空模块：单人本机场景下折叠进设置，避免导航出现无内容页面。
- 不把移动端做成完整编辑端：保留查看、记录、筛选与新建，复杂批量操作留给桌面。
